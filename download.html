GingerFlow ships as a packaged Windows build. There is no installer to run as administrator, no compiler to configure, and no build toolchain to set up.

Windows 64-bit · ZIP archive · version 1.0.1-Beta

Install in four steps

From download to a running canvas in a couple of minutes.

1

Download the release

Open the releases page and download the Windows ZIP asset, for example GingerFlow-1.0.1-Beta-win64.zip.

2

Unblock and extract

Windows may mark files downloaded from the internet. Right-click the ZIP, choose Properties, tick Unblock, then extract to a folder you control such as C:\Apps\GingerFlow.

3

Run the application

Launch GingerFlow.exe from the extracted folder. Everything needed to run the desktop editor ships inside the archive.

4

Optional: add Python

Install Python 3 only if you plan to use Python plugin nodes. Built-in nodes run without it, and GingerFlow can guide the runtime setup on first use.

What is in the package

The archive is self-contained and portable.

GingerFlow.exe

The desktop editor: canvas, toolbox, property inspector, timeline, and output console.

GingerFlow-Cli.exe

The standalone worker for headless execution in scripts, scheduled jobs, and CI pipelines.

Built-in node library

Logic, data, string, file, streaming, archive, database, network, image, email, and utility nodes.

Themes

Light, Dark, Nord, Solarized, and High Contrast, with palette and typography tokens.

Documentation

In-app documentation covering nodes, workflows, plugins, settings, and troubleshooting.

Resources

Icons, fonts, and catalog files backing the editor and node rendering.

First run checklist

A short path from a blank canvas to a workflow you trust.

  1. Build something small. Two or three nodes are enough to learn the canvas, ports, and inspector.
  2. Run it with F5. Watch the timeline and Output console to see exactly what executed.
  3. Save as .fg. Your workflow, configuration, variables, and notes travel together in one file.
  4. Add a branch. Use logic.if and wire value consumers to out, not to a branch port.
  5. Scale carefully. Switch to Stream nodes for large files, and add a Delay in fast loops.
  6. Test before it matters. Use non-production data before pointing a workflow at real systems.

Review before you run. Workflows can delete files, write to databases, execute processes, and call external services. Check paths, credentials, commands, and repeat settings before running against anything important.

Building from source

Only needed if you intend to modify the application itself.

Most users should download the packaged release above. If you are contributing to the codebase, the repository includes a CMake build that requires CMake 3.24 or newer, a C++20 compiler, and Qt 6 with the Core, Gui, Widgets, Concurrent, Network, SQL, and Test modules. See the repository documentation for the full setup, including a no-administrator Windows path.
