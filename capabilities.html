Capabilities

Everything you need to
build real workflows.

GingerFlow is a complete workflow environment: a visual editor, a defensive execution runtime, a broad built-in node library, bounded streaming pipelines, and a Python plugin boundary that grows with your needs.

01

Visual authoring

Compose workflows by placing nodes, connecting typed ports, and configuring values directly on the canvas.

Canvas navigation

Pan, zoom, minimap, alignment grid, grid visibility toggle, and fit-to-view tools keep large graphs manageable.

Typed ports

Inputs and outputs declare their data type. Inline editable values let you configure a node without leaving the canvas.

Wire styles

Choose Bezier, straight, or stepped wires so dense graphs stay readable.

Organisation

Regions, notes, duplication, copy and paste, keyboard navigation, and selection-aware undo/redo.

Discovery

Searchable Toolbox and Quick Node Search match on category, type, and description.

Property Inspector

Configure node parameters and central-widget values in a dedicated panel.

02

Execution runtime

The runtime validates the graph before it runs, then shows its work while it executes.

DAG validation

Cycle detection and topological ordering run before execution so structural problems surface early.

Stale propagation

Only nodes affected by new values are recomputed, keeping iterative runs fast.

Conditional routing

__active_outputs__ selects which output ports are active for a given pass.

Branch control

__stop_branch__ blocks a downstream branch; __enabled__ skips a node entirely.

Repeats and limits

__repeat_node__ schedules another iteration, bounded by per-node Max Iterations.

Retries and cancellation

Configurable retry count and backoff, with cancellation propagated across desktop, worker, and Python execution.

03

Built-in node library

A broad, composable vocabulary rather than a handful of demo nodes. Combine, repeat, branch, group, inspect, and extend.

Logic

if, switch, filter, loop, collect, join, split, merge, combine, delay, stop, unique, flatten, sort, group-by

Arithmetic

addition, subtraction, multiplication, division, remainder, power, rounding, trigonometry, calculation

Strings

concatenate, split, join, substring, search, replace, case conversion, padding, URI encoding, edit distance

Data

partition, aggregate, index, pivot, unpivot, zip, Cartesian product, slice, rename keys, deep merge, JSON diff and patch

Transforms

JSON mapper, JSON path, templates, regular expressions, JSON/YAML/XML/TOML conversion, Markdown

Files

read/write, CSV, checksum, FTP, text files, path and directory operations, copy, move, rename, delete

Streaming

bounded file and CSV pipelines plus batch transform, filter, and aggregate nodes

Archives

ZIP and GZip compression, extraction, and listing

Database

SQL Server, MySQL, PostgreSQL, SQLite, and MongoDB where runtime drivers are available

Network

REST, GraphQL, URL parsing and building, HTTP upload/download, DNS lookup, ping, port checks

Images & Email

image metadata and scaling, SMTP and IMAP operations

Utilities

environment values, timers, random values, ranges, logging, assertions, type conversion, process execution

04

Streaming pipelines

Process large files in bounded chunks or row batches instead of loading a whole dataset into memory.

CSV Stream Read->Stream Filter->Stream Transform->CSV Stream Write
Stream category nodes
NodePurpose
file.stream_readEmit bounded binary chunks
file.stream_writeWrite binary chunks directly to disk
file.csv_stream_readEmit CSV rows in bounded batches
file.csv_stream_writeAppend CSV batches directly to disk
stream.transformTransform each text or binary chunk
stream.filterFilter rows within each batch
stream.aggregateAccumulate values across batches

Plan for scale. Streaming bounds the reader, but downstream nodes and plugins can still build large in-memory values. Pass paths and bounded batches rather than routing an entire large file as one value.

05

Reusable custom nodes

Build a process once, validate it, then package it as a single reusable node.

  1. Select two or more connected nodes on the canvas.
  2. Club them with Club Selected Nodes... from the context menu.
  3. Review the detected boundary inputs and outputs and their data types.
  4. Name the node; it appears in the Custom category.

Custom nodes preserve inner nodes and connections, boundary ports, data types and defaults, internal branching, nested definitions, and external wires. Definitions are embedded into .fg files under custom_nodes so workflows carry their reusable subflows with them.

Reversible. Unclub Node restores the original inner graph. Unclub active instances before deleting a custom definition.

06

Observability

Every run reports what happened, when, and at what cost.

Execution timeline

Live node status and timestamps as the workflow progresses.

Process statistics

Duration, memory deltas, CPU progress, and node counts.

Output console

Logs and bounded payload previews for each node.

Crash capture

Crash logs for desktop and worker processes, plus Windows minidumps.

Flow tracing

Set GINGERFLOW_TRACE_FLOW=1 for detailed routing traces.

Worker isolation

A failed or timed-out Python process cannot corrupt the desktop process.
