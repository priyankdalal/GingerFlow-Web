Installation

Download the packaged release for Windows, extract it, and run the desktop application. No compiler or build toolchain is required.

  1. Open the download page and get the latest release archive.
  2. Extract the ZIP to a folder you control, such as C:\Apps\GingerFlow.
  3. Run GingerFlow.exe.
  4. Optional: install Python 3 if you plan to use Python plugins.

Python is optional. Built-in nodes run without it. A Python 3 runtime is only needed for plugin-backed nodes, and GingerFlow can guide setup on first use.

Your first workflow

Keep the first graph small. Test one branch at a time before adding retries, loops, or destructive operations.

  1. Drag a value-producing node from the Toolbox onto the canvas.
  2. Add a transform, calculation, file, network, or database node.
  3. Drag from an output port to a compatible input port to connect them.
  4. Select a node and configure it in the Property Inspector.
  5. Run with Run Workflow or F5.
  6. Inspect the Output console, timeline, and Process Stats.
  7. Save the workflow as a .fg file.

Fast loops. In a tight repeat loop, add a Delay node of at least 500 ms so UI updates are not over-exhausted and the application stays responsive.

Core concepts

ConceptMeaning
NodeA focused operation with declared inputs, outputs, configuration, and metadata.
PortA typed connection point. Inputs accept values; outputs emit them.
WireA directed dependency from one node's output to another node's input.
WorkflowA saved graph of nodes, connections, configuration, variables, and notes.
ExecutorThe runtime that validates the graph and evaluates nodes in dependency order.
PluginAn installable package contributing Python-backed nodes.

Execution model

Before a run, GingerFlow validates the graph and computes a topological order. Cycles are rejected unless expressed through a node's explicit repeat behavior. During execution the runtime:

  1. Propagates values through active connections.
  2. Executes enabled nodes whose required inputs are available.
  3. Marks affected downstream nodes stale for reevaluation.
  4. Applies control signals and the retry policy.
  5. Publishes node and workflow status to the desktop and worker.

Control signals

SignalEffect
__active_outputs__Selects which output ports are active for this pass.
__stop_branch__Blocks the node's outgoing branch.
__repeat_node__Schedules the node for another iteration.
__enabled__Skips the node and blocks its outputs when false.

Use the per-node Max Iterations setting to bound repeat workflows. A value of 0 means unlimited where supported, so pair it with an explicit stop condition.

Retries

When a node raises an error, the executor retries up to the configured retry count, waiting the configured backoff between attempts. If it still fails, execution stops and the failure is published with its error detail.

Comparators include equals, not_equals, greater_than, greater_than_or_equal, less_than, less_than_or_equal, and contains.

Common mistake. Connecting a value consumer to true instead of out silently blocks it whenever the condition is false. If a downstream node needs the result rather than the branch signal, wire it to out.

Variables and templates

Workflow variables hold values shared across the graph, which keeps configuration in one place instead of duplicated across nodes. Reference them from supported string fields using template syntax, and resolve them at execution time.

Use variables for base URLs, root directories, batch sizes, environment names, and other values that change between runs or environments.

Never store secrets in a workflow. Passwords, tokens, private keys, and connection strings should come from environment values or a secret store, not from .fg files, logs, or screenshots.

Saving workflows

A .fg file stores node IDs and types, positions, connections, input defaults, node configuration, central widget state, workflow variables, viewport information, notes, and embedded custom node definitions.

Because definitions travel with the file, a workflow using custom nodes stays intact when shared. If a definition is unavailable, GingerFlow can expand the saved inner nodes rather than losing structure.

Headless runs

The standalone worker executes a saved workflow without the desktop UI, which suits scheduled jobs, scripts, and CI pipelines.

GingerFlow-Cli.exe path\to\workflow.fg

The worker emits execution events, so you can capture node status, failures, and completion from an automation host.

Troubleshooting

A workflow does not run

Check the Output console and timeline for the first failed node, then verify the graph has no cycle, required inputs are connected or defaulted, port types are compatible, branches are wired to the intended output, and external paths, URLs, credentials, and database drivers are available.

The application becomes unresponsive

Use bounded streaming nodes for large files and add a Delay node of at least 500 ms in fast loops. Stop or cancel long-running listeners and review plugin cleanup behavior.

A plugin is rejected

Confirm plugin.json sits at the ZIP root, the manifest is valid UTF-8 JSON, every entry path is relative to the plugin root, and node type IDs are unique. See the plugin development guide.

Python nodes fail to start

Verify the configured Python interpreter exists and that plugin dependencies installed successfully. Python failures are isolated from the desktop process, but the workflow still fails if a required runtime or package is missing.
